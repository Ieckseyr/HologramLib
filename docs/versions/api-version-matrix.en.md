# Version / API version / macro matrix

This library exposes three numbering schemes; consumers use whichever they need:

| Number | Where | Purpose |
|------|------|------|
| **Plugin release version** | `version` in `manifest.json` | For deployment; has the same name as the git tag (e.g. `26.40.2`), shaped `<BDS major>.<minor>.<patch>` |
| **API version** | the "API version" line of `README.md` | The human-readable capability version (e.g. `1.21.0`) |
| **`HOLOGLIB_API_VERSION`** | `include/hologramlib/HologramLib.h` | **The only version source in code**: compile-time static assertion + `IHologramLib::version()` runtime handshake |

`IHologramLib::version()` returns `HOLOGLIB_API_VERSION` itself, so the runtime handshake and the compile-time assertion read the same value.

## Encoding rule

The format is `0x01` + **the minor version (the middle byte, incremented in hexadecimal)** + the patch digit:

```
1.15.0 -> 0x011500
1.19.0 -> 0x011900
1.20.0 -> 0x011A00   ← after 0x19 it advances in hexadecimal to 0x1A, i.e. 1.20
1.21.0 -> 0x011B00
```

In other words, **each minor version adds +0x1 to the middle byte** (it shows up as `0x19 → 0x1A → 0x1B`); do not read those two hexadecimal characters as decimal.

The patch digit is usually `00`, so `1.19.1` and `1.19.0` share `0x011900` — **you can only gate on the minor version**. Early releases used the last digit to distinguish patches (`0x010701` = 1.7.1).

**This macro is only pushed up when a new version is actually released.** Continuing to add capability domains on a line that has not been released does not change it: the "lowest version I can use" the consumer sees has not changed, and raising the macro would only make old consumers misjudge it as incompatible. **`0x012300` shipped with the official release of `26.40.10`** (view override gained the `AddItemActor` spawn packet: retyping/hiding a dropped item is done in one step from then on), and **on the 26.51 line it ships together with `26.51.3`** (the same batch of capability domains, only the protocol line differs); before that `0x012100` shipped with `26.40.9` (view override `EntityView::skinId` same-id model swap + real entity interaction multicast + ABI layout stamp); `0x012000` shipped with `26.40.8` (view override debris cleanup + five methods appended to `IPlayerNpc` + holographic-text/text domain shrink and completion + `view*` per-field exports); `0x011F00` shipped with `26.40.7` (client view override `IViewOverride`) — before that it was `26.40.5`'s `0x011D00` (fake inventory + sulfur-cube display).

> **One exception (on the record)**: `26.40.3` released the 1.21.0 trade-menu click callbacks, and they were retracted on request right after publication — the trade menu became **display-only**, and `TradeClickEvent` / `TradeActionCallback` / `TradeRawAction` with `ITradeMenu`'s six listener methods were removed wholesale. This is **a shrink, not an addition**, and by this document's convention it should have been a major version (`2.0.0`); it was bumped to the minor version `1.22.0` and written out in the table instead, because that API's public window was a single release and no consumer adopted it. If you already wrote trade-menu click listeners against `1.21.0`, upgrading to `26.40.4` requires deleting those calls (it is a compile-time error, not a silent behaviour change).

> **The second shrink (on the record)**: `26.40.8` removed `IHologramText`'s per-line fake functionality wholesale (8 functions + the in-library self-driven `holoTick`; see the `26.40.8` row in the table below). These functions had been exported since the early domains of `26.10.4`, but there was never a corresponding protocol capability underneath: protocol 2168's text payload is **one whole block** with a single colour/scale, there is no line-spacing field, and rainbow mode only painted the lines white; nothing inside or outside the library consumed the animation offset `holoTick` drove. Given this library's positioning of "basic wheels, no fake functionality", keeping them was worse than removing them — consumers would think they had per-line capability. As with `26.40.3`: the shrink does not get a major version of its own; it ships with the minor version `1.26.0` (> the previous release `1.25.0`) and is written out in the table. **ABI handling (the key difference from 26.40.3)**: the six listener methods deleted back then were at the **tail** of the interface and did not move existing slots; this time the per-line methods sit in the **middle** of `IHologramText`, and deleting them outright would shift `setColor` / `setLocation` / `draw` and everything after them forward — consumer binaries compiled before 1.26.0 and not recompiled would **silently misalign**. So these 8 methods are **kept as deprecated empty slots** in the C++ interface (non-pure + inline empty body + `[[deprecated]]`; calls do nothing / return false), and the vtable slots are exactly the same as in 1.25.0; a recompiled consumer calling them the old way gets a **compile-time deprecation warning** (not a silent behaviour change); on the LSE side the exports are deleted as before. The real slot cleanup waits for the next major version (`2.0.0`).

Also noted: **`0x012200` (= API `1.28.0`) never appeared as a released version** — the number was skipped, no release ever used it, and there is no 1.28.0 row in the table below.

> **`26.51.2` was retracted**: that release was retracted after publication; deploy `26.51.3` directly (the tag `26.51.2` is kept as a historical anchor).

## Full matrix

> **Counting basis (the conclusion of a check during the 2026-10 documentation pass)**: the "N in total" at the end of each row in the table is the record **as of that release**, and it contains one accounting drift —
> the `26.40.8` row records `view*` as `6→16`, whereas the real value in code is `6→17`; that undercount of 1 also made the total recorded then 268 (it should actually be 269).
> `26.40.10` then added `viewItemSpawnHooked`, bringing the 26.51.3 snapshot to 270 `exportAs` calls; `26.51.4` adds 8 more (`itemDisplay*` 33→40, `view*` 18→19).
> **Current count: 273 (26.51.4)** (the two `ghost*` entries are now wired into the registration flow).
> The historical numbers in the table are **kept as in the original and not corrected**.

> **Three further known historical inconsistencies** (likewise kept as in the original and only registered here):
> ① **`26.10.6`'s API version does not match** — this table records `1.15.0` (`0x011500`), while that entry in the [changelog](./changelog.md) writes `1.17.1`; and `1.17.1` does not appear in any row of this table. There is no way to establish which is right (the tag from back then is missing), so **consumers should not gate on the release number 26.10.6**.
> ② **The "cannot do" in the `26.40.7` row has been partially overturned by later releases** — that row asserted "26.40 cannot do per-player scale / glowing / invisibility (the metadata table has no `scale`)", but the `26.40.10` row then added `EntityView::metaScale` through `Reserved38` + `Reserved53·54`. The old entry carries no annotation, so **when reading that 26.40.7 passage, read the 26.40.10 one with it**.
> ③ **Suspected double-counting** — the [changelog](./changelog.md) entry for `26.40.1` (1.20.0) says "new ghost interaction multicast listeners (1.19.1)", while the `26.10.7` entry on the same page already attributes that feature to 1.19.0.

## How consumers use it

```cpp
#include <hologramlib/HologramLib.h>

// 1) Compile time: require a capability domain to exist
static_assert(HOLOGLIB_API_VERSION >= 0x011B00, "requires 1.21.0 (ITradeMenu)");

// 2) Runtime: handshake on plugin enable (the library may have been replaced by an older build)
auto const ver = hologramlib::IHologramLib::getInstance().version();
if (ver < 0x011B00) {
    logger.error("HologramLib too old: 0x{:06X}, need >= 0x011B00", ver);
    return false;
}
```

## Convention for appending a new domain

`IHologramLib`: new capabilities are always appended as virtual functions at the tail of the class, existing methods are not modified or reordered (so the existing methods' ABI stays unchanged), and `HOLOGLIB_API_VERSION` is incremented. Each new domain is recorded on one line in the README changelog and registered in this table.
