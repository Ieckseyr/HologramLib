# 设计说明

这页写 HologramLib 的接口演进规则、功能边界，以及视图覆盖域的限制。它们决定了什么可以放进库、什么必须留在消费方。

## 接口兼容性

`IHologramLib` 与各域接口只在类尾部追加虚函数，既有方法的签名与语义不变。新增能力时同时递增 `HOLOGLIB_API_VERSION`，这是代码侧唯一的版本依据：

- 编译期用 `static_assert(HOLOGLIB_API_VERSION >= 0x012300, "...")` 要求某个能力域；
- 运行期用 `IHologramLib::getInstance().version()` 确认服务端上装的不是旧版库。

两处取的是同一个值，所以两处都写就不会出现「编译过了但运行期炸」。

虚函数在虚表里的位置就是它的身份，因此只能在尾部追加。尾部追加不动既有槽位，用旧头文件编译的消费方二进制仍然安全；在中段插入会让后面所有槽位前移，消费方会静默调用到错误的函数，而不是编译报错。26.40.9 起头文件带虚表布局描述符，消费方编译期自检、库侧运行期拦截布局不一致的消费方。

### 删除已有接口

删除已发布的方法同样会移动槽位，按删除位置分两种情况，都要求在版本表里记录：

| 情况 | 处理 | 实例 |
|---|---|---|
| 删的是尾部方法 | 直接删，抬次版本并在版本表写明 | 26.40.3 交易菜单的六个监听方法 |
| 删的是中段方法 | 保留为废弃空槽（非纯虚 + 内联空实现 + `[[deprecated]]`），虚表槽位不变，留到大版本再清 | 26.40.8 的 8 个悬浮字行级方法 |

两次收缩的原因和迁移方式见 [版本与 ABI 对照](versions/api-version-matrix.md)。

## 功能边界

库提供渲染原语（`create` / `destroy` / `set*`）、协议封装（`AnimateEntityPacket`、`MoveActorAbsolute`、`AddActor` 等发包细节）、时机通知（`setEntitySpawnCallback` 一类回调），以及数据的导出导入原语（`getSkinBlob` / `registerSkinFromBlob` / `importSkins`，都是单次操作，不在库内留状态）。此外的事情留在消费方：

1. 不落盘，不持久化消费方数据。皮肤、实体动画、展示配置都由消费方存储。皮肤的做法是库用 `getSkinBlob` 导出快照，消费方存盘，需要时用 `registerSkinFromBlob` 恢复。
2. 不替消费方决定何时重发什么。库给时机通知（`setEntitySpawnCallback`：实体对玩家 spawn / respawn 完成后回调）和单发原语（`playAnimationTo`：对指定玩家单发动画包）；查什么数据、发不发、数据从哪来都在消费方。
3. 命令、表单、占位符（PAPI）、权限、点击执行命令不进库。

判断一个新能力该不该进库，看它换一个消费方是否还成立：成立（协议层、渲染层、纯时机）就进库；不成立（依赖某个消费方的存储格式或业务语义）就留在消费方。

### 边界划分

| 能力 | 库提供 | 消费方负责 |
|---|---|---|
| 皮肤快照持久化 | `getSkinBlob` / `registerSkinFromBlob` | 存盘、启动恢复、删除清理 |
| 实体动画补发 | `setEntitySpawnCallback` + `playAnimationTo` | 动画名与停止表达式的存储、在 spawn 回调里补发 |
| 皮肤目录导入 | `importSkins`（单次导入，不落盘） | 导入命令、来源展示 |
| 跟随展示显隐 | `follow` / `unfollow` / `setEnabled` | 目标玩家上下线时的显隐决策 |

### 库内定时器

库里会自己跑的定时器只有两类：送达保障（15 s 兜底重发、进服重发、视图覆盖每 tick 心跳、悬浮字动态行 0.5 s 节流刷新）和引擎同路径（粒子域跟随 BDS 的 tick flush 聚合，走原版粒子广播那条路）。

替消费方做动画的定时器不放进来。悬浮字的自驱动画与 `holoTick` 已按这条在 26.40.8 移除。判断一个定时器是否合适，看它是在保证东西送到，还是在决定东西怎么动。完整盘点见[架构总览](architecture/overview.md)。

## 视图覆盖域的限制

客户端视图覆盖（`IViewOverride`）改的是客户端看到的东西，因此另有三条限制。

出站钩子挂在 `NetworkSystem::send` / `sendToMultiple`，只决定这一包发不发，不修改引擎包对象里的字段。需要改内容时丢掉原包，由库自己手写协议包补发。

数据只来自协议包：位置、朝向、输入位来自入站 `PlayerAuthInput`，出生包类型、位置、名字来自出生包载荷，动作来自 `Animate` / `ActorEvent`。不读服务端实体状态，不碰 `getAABB` / `fetchEntity` / `Player::getInventory` 这类接口。唯一例外是身份识别（网络标识换成玩家、`AddPlayer` 里反查 uniqueId）。

读引擎状态的功能不进库。背包镜像（读玩家背包 + 开容器界面 + 按 tick 刷新）曾短暂进过库，已摘除；消费方要用请用容器域的协议能力自己拼：`IContainerMenu::open` 加按槽 `setItem`，读谁的背包、多久刷一次由消费方决定。

`Level::$tick` 心跳（实体重新进入视野、玩家换区块时重推覆盖）与形状域的重发机制不受这几条限制，它们属于时机通知。
